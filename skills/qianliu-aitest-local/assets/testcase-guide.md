# 测试用例格式使用指南

## 支持的用例格式

| 格式 | 文件扩展名 | 适用场景 | 特点 |
|:---|:---|:---|:---|
| **xlsx** | `.xlsx` | 已有用例管理表格、需要完整字段（特性名/用例ID/标签等）| 字段最全，需要 Excel 软件编辑 |
| **json** | `.json` | 程序生成用例 或 基于已有任务中的testcase.json | 结构化，英文 key，开发友好 |
| **markdown** | `.md` | 快速编写、轻量场景、AI 生成用例 | 最简洁，仅需四个核心部分，纯文本可直接编辑 |

---

## Markdown 格式用例编写规范

### 四个核心部分（均为可选）

| 部分 | 说明 | 对应字段 |
|:---|:---|:---|
| `### 前置条件` / `### 前置步骤` / `### 前置` | 用例执行前需满足的环境或数据条件 | `preconditions` |
| `### 操作步骤` | 测试的具体操作序列 | `steps` |
| `### 期望结果` | 每步操作后期望看到的结果 | `expected_results` |
| `### 后置条件` / `### 后置步骤` / `### 后置` | 用例执行完成后的清理/恢复操作 | `postconditions` |

**注意**：四个部分均可独立使用，未出现的部分视为空。编写用例时，默认只需包含 **操作步骤** 和 **期望结果**；前置条件和后置条件仅在用户明确要求时才添加。

---

### 单用例写法

**每个部分均支持多步骤**，步骤之间换行即可。支持以下五种编号格式，混用亦可：

| 格式 | 示例 |
|:---|:---|
| 中文顿号 | `1、内容` |
| 英文点 | `1. 内容` |
| 中文括号 | `1）内容` |
| 英文括号（包围） | `(1) 内容` |
| 英文括号（后置） | `1) 内容` |


**多步骤示例**：

```markdown
### 操作步骤
1、打开浏览器，访问登录页
2、输入用户名和密码
3、点击"登录"按钮
4、等待页面跳转完成

### 期望结果
1、登录页面正常加载
2、表单可正常输入
3、触发登录请求，按钮变为加载状态
4、跳转至首页，显示用户欢迎信息
```

---

### 多用例写法

一个 `.md` 文件可以包含多个用例，用 `---` 分隔，每个用例用 `## 用例标题`（可选）标注：

```markdown
## 用例一：登录成功

### 操作步骤
1. ...

### 期望结果
1. ...

---

## 用例二：登录失败

### 操作步骤
1. ...

### 期望结果
1. ...
```

---

## Prompt 转换示意

执行时，用例的四个部分会被 `buildPrompt()` 合并成一条连续编号的 prompt 字符串发送给 AI Agent：

**原始用例（markdown）：**

```markdown
### 前置条件
1. 系统已正常启动
2. 已存在测试账号 user01

### 操作步骤
1. 打开浏览器，访问 https://example.com/login
2. 输入用户名 user01、密码 pass123
3. 点击"登录"按钮

### 期望结果
1. 登录页正常加载
2. 输入成功后表单有效
3. 页面跳转至首页，显示欢迎信息

### 后置条件
1. 退出登录，清除 Session
```

**转换后的请求服务的 prompt：**

```
1、[前置步骤] 系统已正常启动
2、[前置步骤] 已存在测试账号 user01
3、打开浏览器，访问 https://example.com/login [期望结果] 登录页正常加载
4、输入用户名 user01、密码 pass123 [期望结果] 输入成功后表单有效
5、点击"登录"按钮 [期望结果] 页面跳转至首页，显示欢迎信息
6、[后置步骤] 退出登录，清除 Session
```
